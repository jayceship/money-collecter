# 봉명 재고회수 — P0

전자부품 잉여재고 파일(CSV/XLSX/PDF)을 받아 품목 필드를 추출·정규화하고, 오류·누락·확인 질문을 원문 근거와 함께 내보낸다.

**사업 상태 (2026-11-12 기준):** 재고 위임 0건, 수수료 약정 0건, 확정 견적 0건, 매출 0원.
소프트웨어 테스트 통과는 사업 검증 통과가 아니다. 지시서의 개발 게이트가 미충족이므로 P0만 구현했다.

## 리드 찾기 (v0.2.0)

1. **설정** 탭에 네이버 검색 API 키를 넣습니다(developers.naver.com, 무료). Anthropic API 키는 선택이며, 없으면 키워드 규칙으로 판별합니다.
2. **리드 찾기 실행**을 누르면 네이버 카페(중고나라 포함)와 블로그에서 전자부품 재고 처분 글을 찾습니다. 찾은 글마다 판매자인지 매입업체인지 판별하고, 맞는 매입업체를 붙이고, 연락 초안을 만듭니다.
3. 목록을 더블클릭하면 원문이 열립니다. **연락 초안 복사**를 눌러 쪽지나 댓글로 직접 연락하고, 상태를 바꿔 진행 상황을 관리합니다.

연락처를 자동으로 수집하거나 자동으로 발송하지 않습니다. 연락은 사람이 1:1로 직접 합니다(정보통신망법 50조, 50조의2).
리드 DB 위치: `%APPDATA%\Bomyung\leads.db`

## 바로 쓰기 (EXE)

GitHub Releases에서 `BomyungRecovery.exe`를 받아 더블클릭하면 됩니다. 파일을 선택하고 소유자, 권한 근거, 공유 허용을 입력한 뒤 '처리 실행'을 누르세요. 결과는 EXE 옆 `output` 폴더에 저장됩니다.
코드서명이 되어 있지 않아 Windows SmartScreen 경고가 뜰 수 있습니다. '추가 정보 → 실행'을 누르면 됩니다.

EXE 빌드:

```bash
.venv\Scripts\pyinstaller --noconfirm --clean --onefile --windowed --name BomyungRecovery --paths src launcher.py
```

## 설치·실행 (개발용)

Python 3.12 또는 3.13 필요.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e .[dev]
pytest
```

```bash
bomyung process 재고목록.xlsx --owner "소유자명" --authority "위임장 파일명" --share yes
```

결과는 `output/` 폴더에 생성된다.

| 파일 | 내용 |
|---|---|
| `*.items.csv` | 품목별 원문값(`*_raw`)과 정규화값, 원본 시트·행, 파일 해시 |
| `*.issues.csv` | 오류/경고/정보, 근거 위치 |
| `*.questions.csv` | 소유자에게 물을 질문 목록 (발송하지 않음) |
| `*.summary.json` | 요약, 견적 요청 후보 여부 |
| `*.processed.xlsx` | 위 내용을 시트별로 묶은 파일 |

종료 코드: `0` 견적 요청 후보(P0 기준) / `1` 오류 있음 / `2` 접수 거부.

## 처리 규칙

- 원문값은 그대로 두고 정규화값을 별도 열에 기록한다.
- 품번은 앞뒤 공백만 제거한다. 0/O·1/I 혼동 가능 문자, 내부 공백, 지수 표기(엑셀 손상)는 경고 또는 오류로 표시하고 고치지 않는다.
- 1글자·접미사만 다른 품번은 경고만 내고 서로 다른 품목으로 둔다. 중복 행의 수량도 합치지 않는다.
- 수량: `1k` 같은 축약, 소수, 잘못된 쉼표, 0 이하 값은 오류로 처리하고 값은 비워 둔다. 릴·트레이 단위를 개수로 바꾸지 않는다.
- XLSX 수식은 계산하지 않고 오류로 표시한다. 내보낼 때 `= + - @` 같은 위험 접두 문자는 이스케이프한다.
- `package`/`패키지` 열은 IC 패키지일 수 있으므로 포장 열로 매핑하지 않는다. 매핑하지 않은 열은 요약에 표시한다.
- 소유자, 매각 권한 근거, 공유 허용 중 하나라도 없으면 견적 요청 후보가 될 수 없다.
